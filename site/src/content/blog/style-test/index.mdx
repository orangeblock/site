This is a sample post to check styling. Delete it once real posts exist. Most stutter isn't slow code, it's [work landing in the wrong frame](https://web.dev/articles/rendering-performance). At 60 fps the browser gives you roughly 16.7 milliseconds per frame, and style, layout, paint and compositing all want a share of that before your script runs.[^1]

The fix is usually to call `requestAnimationFrame` less, not more. Batch reads before writes and let the compositor handle anything that only changes `transform` or `opacity`.[^2]

## Code

A normal code block:

```python
from dataclasses import dataclass
from pathlib import Path

import numpy as np

# ~16.7 ms per frame at 60 fps
FRAME_BUDGET_MS = 1000 / 60


@dataclass(frozen=True)
class Mesh:
    """Triangle mesh loaded from a .obj file."""
    vertices: np.ndarray
    faces: np.ndarray

    @classmethod
    def load(cls, path: Path) -> "Mesh":
        verts, faces = [], []
        for line in path.read_text().splitlines():
            if line.startswith("v "):
                verts.append([float(x) for x in line.split()[1:4]])
        return cls(np.array(verts), np.array(faces, dtype=np.int32))
```
